# 局部语义修改与作品续编

以当前作品为权威，读 [共享合同](../../contracts/editorial-contract.md) 与 [通用能力交接](../../contracts/capability-handoff.md)。可使用编辑器项目历史/API 或本库[作品合同](../../contracts/work-contract.md)的本地实现；当前工具的真实能力与语义效果分别核验，不强制迁移成 WorkDocument。

本能力的外部方法引用与后续本地实现边界见[来源与实现记录](../../provenance/fusion-revision.md)。

## 恢复对象与范围

通过当前编辑器的项目读取能力或本地 [work-version](../../atomic/work-version/SKILL.md) read 获取最新作品，结合本轮选区、前一轮指代和用户反馈确定目标。版本核对不等于额外审批。现有清晰授权直接执行；找不到“这句/这一段”时只询问必要定位信息，不把整部片子都重做一遍。

还没登记的作品先检查原工程可获取哪些状态；只在选择本库本地 Work 执行时转换受支持片段/音轨/字幕并记录转换缺口。不能把压平的MP4当成仍有独立字幕和旁白轨的工程；没有分离资产时不要声称可以无损移除烧录字幕或已经混入的人声。

区分用户要分析、候选方案、实际修改、局部采用、局部恢复还是整版回退。采用 [修改策略索引](../../styles/revision/index.md)，继承当前场景主风格；除非用户要求，不改变整体作品风格。

## 将反馈变成具体决定

按 [局部判断规则](references/decision-and-scope.md) 解释“抓人、自然、紧凑、温柔、留白、信息太多”等词。查源素材和上下文，确定改哪些片段/字幕/音轨、为何能改善，以及哪些必须不动。影视沿用人物/因果/揭示约束，口播保留条件与观点强度，教程保留动作与结果证据。

用 [media-inspect](../../atomic/media-inspect/SKILL.md)、[frame-extract](../../atomic/frame-extract/SKILL.md) 核对新增素材。涉及口播切点先走 [speech-plan-compile](../../atomic/speech-plan-compile/SKILL.md)，涉及教程操作链先走 [tutorial-plan-compile](../../atomic/tutorial-plan-compile/SKILL.md)；各自语义判断仍由本层按场景规则完成，不能把编译器当决策模型。

“后面不动”至少冻结后段内容；如有配乐节拍、字幕绝对位置或明确时间要求，还要冻结输出位置。要求同时缩短和保持后段时间时不能静默冲突；优先等时长替换，无法同时满足再提出具体取舍。

采用旧候选字段或处理跨轮次冲突时，读 [三方局部采用协议](references/field-adoption.md)。核实共同基线、donor、最新作品和稳定对象身份，先由本层确定授权范围与冲突取舍，再按协议合成候选。插入、删除、重排要单列结构操作并检查锚点/依赖；不能复活已删除对象。只有选择本库本地 Work 且只采用已有标量字段时，才可用确定性辅助脚本；非 SQLite 项目使用自身修订标识和条件写入，不伪造 Work token。辅助脚本不判断风格，不提交作品。

## 候选、提交与导出

形成当前工具可执行的候选和精确修改范围；选择本库本地 Work 时形成 WorkDocument 并调用 [timeline-revise](../../atomic/timeline-revise/SKILL.md)。审读 revision-diff：哪些内容变了、哪些位置变了、哪些字幕/音轨随锚点移动。缺必要支持的效果要明确登记，不用风格元数据冒充画面已改变。

用户要求先看候选时，以**最新作品加本轮拟采用修改后的完整候选状态**制作预览，正式作品头不提交。使用当前编辑器时走其隔离候选/临时预览能力，逐层核对原主轨、配乐/音轨、已有视觉叠层和字幕都仍在；局部只改开头也不能把后段层状态丢掉。选择本库本地 Work 时先由 timeline-revise 形成完整 work-candidate/1，再以 work-render 的 preview_candidate 分支对当前 store/expected_version 做只读基线核验，按主轨→混音→叠层→字幕→技术检查渲染；预览不调用 work-version commit、restore 或正式交付指针写入。预览失败或并发手改后保留当前头，旧预览只作历史，采用时重新核最新头与受限范围。已要求执行的明确修改可用当前编辑器的受限写入或本地 work-version commit；无需新增批准环节。

提交冲突时重新读当前版本，比较新人工编辑与本次意图。无冲突部分重新生成候选；有实质冲突时保留人工编辑并指出矛盾，不能只替换 expected_version。提交后用当前工具导出并读回绑定版本；选择本库本地 Work 时可用 [work-render](../../atomic/work-render/SKILL.md)。若渲染期间作品已变，旧输出保留为历史，继续处理当前版本所需交付。

## 验收与恢复

按 [修改验收](references/evaluation.md) 检查目标是否改善、冻结项是否保持、修改接点与下游映射是否成立；技术检查通过不能代替审美与听检。交付当前版本、差异、视频/字幕、剩余问题，以及可恢复的历史序号。

“只采用第二版的开头”以共同基线、第二版和最新版本逐字段比较，只迁入授权源范围并保留最新音量/字幕等手改，重新核对衔接和输出位置；“撤销刚才改的字幕，别动其他内容”局部恢复字幕，不能整版回退。明确整版回退时才使用 work-version restore。每次修改留一份连续历史，不新建一套平行权威文件。

局部恢复按 [跨轮次恢复与媒体对照](references/evaluation.md#跨轮次恢复与媒体对照) 执行：从历史版本取出授权字段，合入最新文档；以恢复前的最新版作保持项对照。历史版本只提供恢复值，不能作全部保持项的比较基线。

## 参数配方与复验计划

明确要求改变字幕包装或指定音轨增益时，可将选定风格卡与可执行参数绑定，通过 [style-recipe-compile](../../atomic/style-recipe-compile/SKILL.md) 生成普通 Work 候选。它不决定风格、不自动兑现卡片全部语义；卡片来源和实际参数分别记录。

候选可用 [revision-impact-inspect](../../atomic/revision-impact-inspect/SKILL.md) 输出摘要绑定的阶段影响。保留原 revision-diff 的保守复验要求；“输入没变”不是缓存已核验，也不是旧成片的听检、视觉或内容结论已适用于新版本。预览采用和提交继续使用同一份候选及 Work 版本冲突保护。
