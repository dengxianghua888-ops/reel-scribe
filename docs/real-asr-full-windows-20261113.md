# 真实本地 ASR 与完整九格窗口

本轮推进真实任务，而非扩大短窗参数演示。ASR 核心冻结于 `7c2e47a`；九格渲染复用 `c4edca0`（其树等同远端 `7695b177`）。两组证据分别核验，不混称同一版本或整体验收通过。

## 实际故障及修复

官方 faster-whisper 1.2.1 在 PyAV 19.0.2 下，首条真实中文录音失败：`open() got an unexpected keyword argument 'metadata_errors'`。同模型在独立 PyAV 16.0.1 环境成功，失败记录未删除。产品此前已由 FFmpeg 生成 16kHz、单声道 PCM16 WAV，却再次让 Whisper 经 PyAV 解码。现只把已绑定规范 WAV 严格读取为 float32 样本交给 Whisper，避免多余解码依赖；未改变识别模型、词时间规范化或审核状态。

严格校验覆盖 RIFF 总长度、完整 chunk 边界及填充、唯一 fmt/data、PCM 格式/byte rate/block align、非空完整帧；读取和推理后复查输入身份。只支持产品自己生成的标准 WAV，不宣称通用 WAV 兼容。独立审查发现的尾随数据、重复 data、缩短声明及错误格式参数均已修复。保留模型/环境锁和原始观察，不自动纠错、剪词或认证声学对齐。

- 已有许可来源中的 FLEURS 普通话 validation 第 0、8、10、11 行真实录音，CC BY 4.0。模型识别与数据集参考独立保存；参考不是听审金标。许可与原始出处沿用既有素材记录，不将模型权重或数据集复制进产品包。

两环境修改后均完成四条真实识别。可见参考差异包括“警告称/警告成”“柏油/板油”，以及繁简、标点；这些是待核差异，不按参考静默纠正。数字、否定词可做逐项人工复核，但文本相似不是听审或事实正确性的证明。独立 PCM 对照中，四条规范 WAV 的数组与 av16 解码及 FFmpeg f32 解码逐样本相同。新 av19、新 av16 与旧 av16 的完整 segments、词起止/概率、规范 WAV/PCM 字节也逐项一致；词数分别42/26/28/12。已有 transcript-reference-compare 产生四份 exact 差异报告（3/8/6/4处），保留原稿，不宣称 CER 或听审准确率。

## 九个完整声明窗口的实际产品输出

不是外部 FFmpeg 切片代替产品：九个窗口均经 Work/render 生成，完整解码、帧数、声明源窗时长通过。64 个报告绑定产物哈希复核一致。

| 类别 | 正常 | 复杂 | 误导风险 |
|---|---:|---:|---:|
| 影视（24fps） | 6s /144帧 | 20s /480帧 | 6.5s /156帧 |
| 中文语音（50fps） | 5.58s /279帧 | 11.46s /573帧 | 13.92s /696帧 |
| 教程（30fps） | 6s /180帧 | 28.1s /843帧 | 63.7s /1911帧 |

每格故意截去末一秒均拒绝，首个失败保护为 `complete-audio-once`；不宣称分别击穿全部视频保护。预览/拒绝不改 Work 头。影视三格源自同片重叠窗口，不是九份独立素材；语音用真实 PCM 配合合成背景，参考字幕不是这次 ASR，最终 AAC 也不称无损。教程原 WebM 拒绝保留，显式有损标准化后按100ms网格向外对齐：复杂格多尾60ms，误导格多头50ms/尾60ms，映射单列且不改原 manifest。

九格记录当时“ASR 环境未准备”的说明是历史状态，本轮已解除，不能继续作为当前阻塞。曾有浮点帧边界拒绝与外部记录脚本排他写失败，原记录保留；产品渲染本轮无失败。
