# HDR 输入转换真实内容操作记录（2026-11-21）

本页记录 C4a `color-input-transform` 在真实照片内容上的一次运行。**HDR 素材是合成的**：把真实照片做成的 SDR 视频用 zscale 编码为 HLG 与 PQ，不是摄影机或手机原生拍摄的 HDR。结论只覆盖下文的素材、参数和环境：它属于真实内容上的技术验证，不是人工审美验收。

## 素材与执行

- **SDR 源**：[作品调色真实素材操作记录](color-work-real-run-20261120.md)第二部分的未调色时间线，96 帧，依次为宇航员、咖啡、猫、火箭四镜。
- **合成 HDR**（4:2:0 10 位，libx264 CRF 10，BT.2020 标签齐全）：
  - **HLG**：SDR 白放在 100 尼特；
  - **PQ**：SDR 白放在 1000 尼特，相当于整张画面的亮度乘以 10，是比真实 HDR 调色更极端的高光情形。真实 HDR 一般把漫反射白放在约 200 尼特，只有高光到 1000 尼特。
- **执行**：通过 `python3 runtime/editing_runtime.py run` 调用 `color-input-transform`，`nominal_peak_nits` 为 100，采样第 12、36、60、84 帧，输出 `yuv420p`；四次调用都成功，输出均带 BT.709 标签，帧数不变。环境为 FFmpeg 6.1.1（zscale、tonemap）、Python 3.13、numpy 2.5。`color_input_ops.py` 的 SHA256 前 16 位为 `5754eb480e070474`。

## HLG 往返（clip）

- **实测**：峰值最大 114.96 尼特，99.9 分位 99.76，99 分位 84.54；超过参考白 1% 以上的像素 0.77%，BT.709 色域外 0%。
- **提示**：因为有超白像素，回执给出“clip 会裁掉 0.77%”的提示。这些像素来自 4:2:0 色度在颜色边缘的过冲，以及编码噪声。
- **与原 SDR 比较**：逐片段中位 ΔE2000 为宇航员 0.77、咖啡 0.75、猫 0.88、火箭 0.66，与此前 SDR 色彩链路的读回误差在同一量级。

## PQ，白色在 1000 尼特：算子对比

- **实测**：峰值最大 1145.6 尼特，99.9 分位 995.07，99 分位 841.36；超过参考白的像素 70.1%，色域外 0.006%。
- **提示**：clip 收到“将裁掉 70.10%”的提示；mobius 与 hable 用峰值 1000 尼特，与实测相符，没有提示。

**逐片段**（每镜 3 帧；L* 中位 / L* p99 / 高光剪切比例）：

| 片段 | clip | mobius，峰值 1000 | hable，峰值 1000 |
|---|---|---|---|
| 宇航员 | 69.5 / 98.4 / 44.8% | 67.8 / 97.8 / 11.1% | 63.8 / 97.2 / 2.4% |
| 咖啡 | 64.6 / 95.8 / 51.3% | 62.3 / 95.7 / 8.9% | 55.4 / 95.4 / 3.4% |
| 猫 | 80.3 / 91.6 / 61.2% | 76.3 / 89.8 / 0.2% | 66.5 / 84.7 / 0% |
| 火箭 | 55.8 / 92.1 / 21.0% | 49.6 / 87.9 / 0.7% | 33.4 / 83.4 / 0.3% |

- **clip**：大片裁切，宇航员的脸完全过曝。
- **mobius**：保留了大部分中间调亮度，高光剪切明显减少，但画面仍偏亮。
- **hable**：剪切最少，脸部细节保留最好，但整体更暗、对比更平，火箭夜景的中间调从 55.8 降到 33.4。
- 没有哪种是“正确”的：这组 PQ 是整体乘以 10 的极端情形，换成真实 HDR 调色，三者的差别会不同。

**读回目视**（代理检查，不是人工验收）：并排看第 12 帧与第 84 帧，结论与上面的数值一致。火箭一镜因为合成时整体提亮了 10 倍，夜空在三种算子下都变成了明亮的蓝色，这是合成方式造成的，不是算子的问题。

## 实现中发现并修正的问题

- **测试素材的 `npl` 放错了位置**：最初给 PQ 合成的 1000 尼特测试素材实测只有 120 尼特。原因是 zscale 的 `npl` 只作用于编码 HDR 的那一级，测试里设在了另一级。原子本身无误，已修正测试。
- **阈值过严**：
  - “超过参考白”最初用 1e-6 作阈值，10 位量化让白色本身（1.0029）也被计入。改为超过 1% 才计入。
  - “色域外”最初也是 1e-6，HLG 往返中 5.6% 的像素因量化噪声被计为色域外。改为低于参考白的 −1% 才计入，现在为 0%。

## 不能据此声称

- 素材是合成 HDR，不代表手机或摄影机原生 HLG/PQ、杜比视界的实际表现；原生素材的场景亮度分布、元数据和编码都不同。
- 不代表任何算子更好；算子和峰值仍由调用方根据画面和回执里的实测决定。
- 只测了每镜 3 帧（测量用 4 帧）。
