# 胶片质感真实素材操作记录（2026-11-21）

本页记录 C4b `film-texture-apply` 在真实照片素材上的一次运行。媒体与回执没有入仓。结论只覆盖下文的素材、参数和环境：属于真实内容上的技术验证，不是人工审美验收，也不代表模拟了任何胶片。

## 素材与执行

- **素材**：[作品调色真实素材操作记录](color-work-real-run-20261120.md)第二部分中，warm-teal 预览经过调色后的视频：96 帧，420×280，24 fps，带 sRGB 标签。按“先调色、再加质感”的顺序，直接在调色结果上施加。
- **参数**：
  - 光晕：阈值 0.8，半径 16 像素，强度 0.5，色调 (1.0, 0.35, 0.15)；
  - 暗角：强度 0.3，起点 0.45；
  - 颗粒：0.02，粒径 1 像素，亮度模式，中间调加权，逐帧，种子 2026。
- **执行**：通过 `python3 runtime/editing_runtime.py run` 调用，成功；输出 96 帧，用时 7.1 秒。读回第 12、36、60、84 帧，即每个镜头的中间帧。环境为 FFmpeg 6.1.1、Python 3.13、numpy 2.5，`texture_ops.py` 的 SHA256 前 16 位为 `156f99d932b64ec5`。
- **重跑说明**：PR #31 两轮评审修复（零起点恒定帧率与旋转校验、读回只读第一条视频流、取消与无进展监督、保留样本宽高比）之后，用同一请求重跑，`texture_ops.py` 的 SHA256 前 16 位为 `9f25d84322056b86`，用时 7.5 秒。源的 SAR 为 1:1，输出现在也写入 1:1，所以文件 SHA256 与修复前不同；解码后的像素逐字节相同，读回数值逐项相同。这条素材本身就是零起点恒定帧率、无旋转、单视频流。

|---|---|---|---|---|
| 12 宇航员 | 0.28 / 0.83 | (0.0239, 0.0127, 0.0071) → (0.0240, 0.0127, 0.0075) | 2.062 / 1.790 / 1.789 | 0.0144 / 0.0148 |
| 36 咖啡 | 0.21 / 0.60 | (0.0082, 0.0086, 0.0077) → (0.0081, 0.0086, 0.0083) | 0.727 / 0.626 / 0.627 | 0.0153 / 0.0157 |
| 60 猫 | 0.26 / 0.65 | 0 → (0.0001, 0.0000, 0.0003) | 1.050 / 0.904 / 0.905 | 0.0184 / 0.0188 |
| 84 火箭 | 0.23 / 0.79 | (0.0018, 0.0008, 0.0006) → (0.0025, 0.0008, 0.0009) | 0.266 / 0.215 / 0.215 | 0.0113 / 0.0116 |

- 三项效果的实测贡献都与预测吻合。颗粒的实测标准差比预测高约 3%，多出来的是编码噪声；均值差小于 0.0002，没有整体偏亮或偏暗。
- 猫这一镜没有超过阈值的高光，预测的光晕为 0，实测也接近 0。
- 咖啡一镜的光晕三通道接近相等：亮部主要是白色杯沿和碟子反光。光晕取高光的最大通道，再乘以色调，所以这里的颜色主要来自高光本身。

**读回目视**（代理检查，不是人工验收）：
- 宇航员一镜，头盔与白色背景的高光周围出现暖色辉光，四角变暗；
- 火箭夜空可见颗粒，灯光周围有轻微光晕。

## 实现中发现并修正的问题

- **取整偏差**：最初的直通链路（16 位 RGB → 4:2:0 → 解码）让画面整体偏暗约 0.006，大约相当于 8 位下 1.5 个码值。这个偏差淹没了光晕的增量，火箭一镜甚至测出负值。原因是 swscale 默认的取整方式；改用 `accurate_rnd+full_chroma_int` 后，偏差降到 1e-4 量级，读回中位 ΔE2000 从约 0.6 降到约 0.25。同样的检查表明，已有的 `color-lut-apply` 走浮点路径，没有这个偏差：恒等 LUT 下均值差约 1e-4。
- **逐像素读回不适用于颗粒**：逐像素比较时，RGB 模式的颗粒经 4:2:0 有损编码后无法与预测一一对应（中位 ΔE2000 约 3.6）。门禁改为低通后比较，各效果的贡献另行测量。
