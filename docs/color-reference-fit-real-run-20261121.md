# 参考色彩迁移、反馈调整与参数模板真实素材操作记录（2026-11-21）

本页记录 C3a `color-reference-fit` 在真实照片素材上的两组实验、C3b `color-grade-adjust` 的一组反馈调整实验，以及 C3c 风格卡参数模板对拟合的约束效果。媒体与回执没有入仓，这里给出来源和可复核的数值。结论只覆盖下文的素材、参数和环境：它属于**真实内容上的技术验证**，不是人工审美验收，也不是最终交付。

## 素材与执行

- **素材**：[作品调色真实素材操作记录](color-work-real-run-20261120.md)第二部分的两条 96 帧视频，均为 420×280、24 fps，带 sRGB（`iec61966-2-1`）标签：
  - **未调色时间线**：4 个片段依次为宇航员（第 0–23 帧）、咖啡（24–47）、猫（48–71）、火箭（72–95）；
  - **warm-teal 预览**：同一时间线套用 warm-teal 调色层（白平衡、S 曲线、HSL）后的输出。
- **执行**：通过 `python3 runtime/editing_runtime.py run` 依次调用 `color-reference-fit` → `color-grade-compile`（65 阶）→ `color-lut-apply`，三者都成功。环境为 FFmpeg 6.1.1、Python 3.13、numpy 2.5。
- **重跑说明**：实验 A、B、D 的数值来自 PR #30 评审修复后的重跑。修复了两处：直方图曲线合并并列码值；JS 直方图的 a*/b* 范围扩到 ±128。这几张照片码值丰富，也没有 b* 低于 −100 的像素，所以 CDL 方法的数值不变；直方图方法的拟合残差中位数从 0.34 降到 0.27，其余变化在 0.02 以内。

## 实验 A：同内容，还原已知的 look

- **设置**：参考是 warm-teal 预览中的咖啡镜头（第 28、36、44 帧），目标是未调色时间线的同一镜头、同样三帧。
- **为什么这样设计**：目标套上 warm-teal 之后应当得到的结果是已知的，所以除了分布距离，还能逐像素比较“拟合出的调色层套用后”与“真实 look”之间的差。

**分布距离**（与参考比较；三个数分别为迁移前 / 理想迁移 / 拟合后）：

| 方法 | 平均色 ΔE2000 | 切片 Wasserstein（Lab） | Lab 直方图 JS 散度 |
|---|---|---|---|
| reinhard-lab → CDL | 2.69 / 0.47 / 0.71 | 4.99 / 1.55 / 1.46 | 0.107 / 0.017 / 0.022 |
| mvgd → CDL | 2.69 / 0.37 / 0.36 | 4.99 / 1.25 / 1.29 | 0.107 / 0.014 / 0.020 |
| histogram → 曲线 | 2.69 / 0.09 / 0.09 | 4.99 / 0.33 / 0.33 | 0.107 / 0.0066 / 0.0063 |

**拟合残差**（理想迁移与拟合结果逐像素 ΔE2000，中位 / p95）：reinhard-lab 1.27 / 3.08，mvgd 0.75 / 3.73，histogram 0.27 / 0.73。

**套用后与真实 look 的逐像素比较**：先编译拟合出的调色层，再用 `color-lut-apply` 套到未调色时间线上，在同样三帧上与 warm-teal 预览比较。

| 调色 | 中位 / p95 ΔE2000 |
|---|---|
| 不调色 | 3.78 / — |
| reinhard-lab（CDL：slope 1.05/1.10/1.07，saturation 1.20） | 1.77 / 3.84 |
| mvgd（CDL：slope 1.06/1.05/1.00，saturation 1.26） | 1.86 / 4.34 |
| histogram（逐通道曲线） | **0.81** / 2.09 |

逐通道曲线最接近真实 look，符合预期：warm-teal 本身含曲线和 HSL，CDL 只能近似。两种 CDL 拟合把与真实 look 的差距缩小了一半左右，饱和度分别拟合为 1.20 和 1.26，与 warm-teal 提高橙色、青色、蓝色饱和度的方向一致。

## 实验 B：跨内容，统计匹配的局限

- **设置**：参考是 warm-teal 预览中的宇航员镜头（第 4、12、20 帧），目标是未调色的火箭夜景（第 76、84、92 帧）。两个画面内容完全不同。

| 方法 | 平均色 ΔE2000 | 切片 Wasserstein | JS 散度 | 拟合残差 中位 / p95 |
|---|---|---|---|---|
| reinhard-lab → CDL | 33.26 / 3.48 / 4.68 | 26.25 / 9.67 / 12.50 | 0.446 / 0.219 / 0.312 | 7.53 / 20.28 |
| mvgd → CDL | 33.26 / 2.42 / 4.95 | 26.25 / 8.28 / 11.80 | 0.446 / 0.193 / 0.333 | 8.76 / 21.05 |

所有距离都大幅下降，但画面不能用：

- 拟合出的参数很极端：绿、蓝通道 slope 超过 2，红通道 offset 约 +0.4，蓝通道 offset 约 −0.4，饱和度 0.57–0.69；
- 读回目视（代理检查，不是人工验收）：蓝色夜空变成粉橙色，脚手架和地面泛橙，夜景氛围完全丢失；
- 拟合残差中位 7.5–8.8，CDL 远不足以表达这样的统计迁移。

这正是合同里写的局限：统计量不看内容和构图，距离变小不等于观感接近。它也说明下一步（C3c）需要风格卡的参数模板：用参数区间和强度上限挡住这类极端结果，而不是把距离变小当作成功。

## 实验 C：反馈调整（C3b）

- **设置**：基础调色层是 warm-teal（白平衡、S 曲线、HSL，`srgb-sdr-display`）。模拟两条反馈：
  - “冷一点、淡一点” → `warmth: -1, saturation: -1`；
  - “对比再强一些” → `contrast: 2`。
- **执行**：依次调用 `color-grade-adjust` → `color-grade-compile`（65 阶）→ `color-lut-apply`，套在未调色时间线上，与只套基础调色层的结果比较。全部成功；探针方向核对全部通过。`color_adjust_ops.py` 的 SHA256 前 16 位为 `1a0d38f177ec7716`。
- **追加的操作**：
  - 冷且淡：`white_balance` gains (0.975, 1, 1.025)，`cdl` saturation 0.92；
  - 对比：master 曲线把 0.25 移到 0.21、0.75 移到 0.79。

**逐片段实测**（每镜 3 帧，平均 b* / 平均色度 / 亮度 p95−p5）：

| 片段 | 基础 | 冷一点、淡一点 | 对比 +2 |
|---|---|---|---|
| 宇航员 | 15.64 / 24.55 / 90.39 | 13.61 / 22.01 / 90.34 | 16.50 / 25.75 / 92.70 |
| 咖啡 | 39.55 / 51.69 / 83.55 | 36.29 / 47.27 / 83.79 | 41.21 / 54.67 / 87.09 |
| 猫 | 27.10 / 31.76 / 48.18 | 24.28 / 28.30 / 48.42 | 30.27 / 36.18 / 54.71 |
| 火箭夜景 | −17.85 / 22.33 / 37.56 | −17.15 / 21.13 / 37.39 | −17.97 / 22.92 / 37.14 |

- 前三镜都符合预期：冷且淡时 b* 与色度下降；对比加强时亮度跨度变大（同时色度略升，S 曲线的常见副作用）。
- **火箭夜景是两个反例**：
  - “冷一点、淡一点”后，平均 b* 从 −17.85 升到 −17.15，蓝色反而变少：画面以蓝色为主，降饱和在收缩蓝色，这一效果超过了变冷。
  - “对比 +2”后，亮度跨度略降（37.56 → 37.14）：S 曲线以中灰为轴，暗场画面大部分在中灰以下，整体只是被压暗，跨度没有变大。
- 探针核对只保证参数在中性和典型颜色上的方向，不保证每种画面都朝说法的方向变化；这两个反例说明调整后仍需预览，必要时针对具体画面换一维调整（例如夜景想“更冷”时不同时降饱和）。

**读回目视**（代理检查，不是人工验收）：咖啡与宇航员两镜，“冷一点、淡一点”可见变冷、变淡，“对比 +2”可见暗部更深、橙色更浓，变化幅度克制。

## 实验 D：用风格卡参数模板约束拟合（C3c）

- **设置**：用“跨镜颜色连续”卡的模板区间（slope 0.9–1.1，offset −0.04–0.04，饱和度 0.85–1.15），重跑实验 A 与 B 中的 reinhard-lab 与 mvgd。其余设置不变，同样经 compile、apply 读回。`color_fit_ops.py` 的 SHA256 前 16 位为 `3918a108b4fd374d`。

**同内容（咖啡）：约束几乎没有代价**

| 方法 | 套用后与真实 look 的中位 ΔE2000（无约束 → 有约束） | 触到边界的参数 |
|---|---|---|
| reinhard-lab | 1.77 → 1.85 | G 通道 slope、offset，饱和度（1.15） |
| mvgd | 1.86 → 1.79 | R 通道 offset |

warm-teal 本身是温和的 look，统计迁移需要的参数大多落在模板区间内。

**跨内容（火箭夜景）：约束挡住了极端结果**

| | 无约束（mvgd） | 有约束（mvgd） | 有约束（reinhard-lab） |
|---|---|---|---|
| 顶部天空平均 L* / a* / b*（调色前 12.8 / 3.7 / −22.0） | 29.7 / 18.5 / **+10.1** | 18.1 / 0.0 / −17.6 | 18.1 / −0.9 / −16.5 |
| 与参考的平均色 ΔE2000（调色前 33.26） | 4.95 | 30.30 | 30.34 |
| 切片 Wasserstein（调色前 26.25） | 11.80 | 24.03 | 23.87 |

- 无约束时夜空变成粉橙色（b* 由负变正）；有约束时仍是蓝色夜景，只是略提亮、略降饱和。
- 代价是距离只下降了一点：参考是白天的人像，目标是夜景，本来就不该“迁移”过去。
- 所有 slope、R/G offset 与饱和度都触到了边界。`bounds.hit` 大面积为真，说明统计迁移想走得远得多，被模板挡住了；这本身是该放弃参考拟合的信号。
- 这一场景同时命中该卡的禁用条件“参考与目标不是同一场景或同类光线（例如日景参考套夜景）”。按工作流，查到禁用条件就不应进入拟合这一步；这里刻意跑一次，是为了验证约束本身的效果。

**读回目视**（代理检查，不是人工验收）：并排看第 84 帧，有约束的版本与调色前接近，无约束版本的天空和脚手架整体泛粉橙。

## 不能据此声称

- 不代表任何方法“效果更好”：实验 A 中 histogram 更接近，是因为真实 look 恰好含逐通道曲线；换成以 CDL 为主的 look，结论可能相反。
- 实验 A 是“已知答案”的技术校验，不是参考风格迁移的效果验证。真正的参考匹配（不同素材、真实参考片）需要人工盲测，尚未进行。
- 只采样了每镜 3 帧；素材仍是静态照片推近的视频。
- 实验 C 的步长是固定参数增量；“一步”在不同画面上的观感不同，火箭夜景已经出现了与说法相反的统计变化。
