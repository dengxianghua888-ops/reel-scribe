# 影述与剪辑 Agent 架构迭代方案 v2：原子下沉、入口收窄、先测后扩

2026 年 11 月 27 日 · 设计方案（未实现、未验收） · 收敛目标：剪辑 Agent

本方案在[多风格优化方案](../multi-style/README.md)（下称“多风格方案”，分支提交 `a815e5c`）的基础上做整体迭代。依据有三份：

- 一次覆盖技能评测、工具粒度、多代理对照、视频剪辑 Agent、开源剪辑项目、AI 短剧生成和评测方法的深度调研，结论整理成[分享文章第二版](https://github.com/dengxianghua888-ops/agent-architecture-notes/blob/claude/affectionate-newton-7kqyfe/articles/agent-and-skill-orchestration.md)；
- 对本仓库、剪辑 Agent 研究资料库和精品短剧 Skill 的只读审计；
- 对多风格方案 13 章与短剧侧《多风格导演体系》12 章的逐章审读。

生成侧的迭代见精品短剧仓库的[《12 迭代方案 v2》](https://github.com/dengxianghua888-ops/premium-ai-short-drama-skill/blob/claude/affectionate-newton-7kqyfe/%E6%96%B9%E6%A1%88/%E5%A4%9A%E9%A3%8E%E6%A0%BC%E5%AF%BC%E6%BC%94%E4%BD%93%E7%B3%BB/12-%E8%BF%AD%E4%BB%A3%E6%96%B9%E6%A1%88v2.md)。

## 一句话结论

**保留影述最强的两样东西：判断与执行分层、可对账的写入。改掉拆分的方向：原子操作下沉为编译器和运行时内部可单测的单元，模型只面对约 10 组带类型的组合入口；路由从常驻长文改为少量硬规则加检索；能独立取证的工作交给只读助手并行，写入工程只留一支笔；新的风格包、组件、原子一律先过测量阶梯再进入路由。** 多风格方案里“刻面正交、风格包编译、基线为门、三个方向”的骨架全部保留；它的扩张节奏、模型可见面和盲评统计口径需要调整。

## 为什么要改：四个现状数字

| 现状（2026 年 11 月 27 日 main） | 说明的问题 |
| --- | --- |
| 注册 69 条（原子 51、场景工作流 17、生成适配器 1），每个原子一份说明 | 知识层拆得最细，模型每次要在 69 个入口里选 |
| 路由协议 `router.md` 26,767 字节，入口 Skill 要求每次读完 | 常驻上下文约 2.2 万 token（估算）；路由准确率从未测量，引用的评测集文件不存在 |
| MCP 只有 `diagnose_installation`、`list_skills`、`run_operation` 三个工具，约 50 种操作走同一个 `run_operation` | 模型可见面最粗：一次局部改稿要连续 5–6 次严格 JSON 调用，手工搬运哈希和版本号 |
| 580 张风格卡全部 `authored-unvalidated`；多风格方案再规划 264 个风格包、126 个组件、19 个新原子 | 扩张先于测量；外部研究中技能负迁移并不少见 |

与此同时，作品版本、候选范围、保护项、三方撤销、回执和读回这一侧，已经是开源剪辑 Agent 中少见的扎实实现。这部分是护城河，v2 不动它，只补“修改编号”和读回分级两处。

## 需要你拍板的决定

1. **冻结扩张。** 阶段 1 放行前，不新增原子、风格卡、风格包和组件进入路由；多风格方案的目录数据继续维护，但只作 `catalog-draft`。
2. **模型可见面重构。** 新增约 10 组命名空间工具，`run_operation` 保留为兼容入口（不再写进入口 Skill 的推荐路径）。这会改变 Claude Code / Codex 用户看到的工具列表。
3. **阶段 B 的状态权威。** 外部 Agent 接入自研剪辑 Agent 时，以宿主工程为唯一权威，影述 SQLite Work 只用于离线与本地 CLI。宿主按[Work 合同](../../contracts/work-contract.md)实现一致性测试。
4. **评测资源。** 路由评测集（约 240 条）由谁标注；盲评池（多风格方案提出 30 位观众、5 位剪辑师）由谁组织；实验预算（模型 token 与即梦积分）各设多少上限。
5. **第一条纵切。** 建议以“口播精剪 + 局部修订 + 一个设计系统族的 3 个包装包”作为阶段 1 的唯一纵切，与研究库“先口播精剪与实拍单品”的顺序一致。
