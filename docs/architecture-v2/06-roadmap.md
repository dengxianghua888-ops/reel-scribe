# 06 路线图：四个阶段，每一步都有放弃条件

多风格方案按 A 离线验证 → B 外部接入 → C 应用内置排期。v2 在 A 之前加一个“测量与冻结”阶段，并把 A 收成一条纵切。每个阶段写明交付、放行条件和放弃或转向条件。工期没有写死：阶段 0 的实测会决定后面各项的规模。

| 阶段 | 对应 | 一句话 |
| --- | --- | --- |
| 0 测量与冻结 | A 之前 | 先知道现状：路由准不准、长链能否次次做对、钱花在哪 |
| 1 收窄与纵切 | A 离线验证 | 口播精剪加局部修订，一条链路走通，模型可见面收窄 |
| 2 取证层与宿主接入 | B 外部接入 | 只读取证并行；剪辑 Agent 工程成为唯一权威；短剧生成接入 |
| 3 应用内置与按证据扩张 | C 应用内置 | 卡片入口、偏好数据、风格记忆；只扩张过了门的家族 |

## 阶段 0：测量与冻结

| 交付 | 说明 |
| --- | --- |
| 冻结 | 新原子、风格卡、风格包、组件不进入路由池；多风格目录保持 `catalog-draft` |
| 遥测汇总（E0） | 从现有回执汇总每任务的调用数、token、时长、读回结果；补齐缺失字段 |
| 评测批跑骨架（H4） | 冻结初态、独立工作目录、3 次重复、成本记录 |
| 路由评测集 | 240 条，6 类，含近邻与应弃权；两人标注；放入 `evals/`（`router.md` 已引用该位置） |
| E1 | 路由集上的 Hit@1 与端到端 Oracle / Auto / None |
| 现状 pass^3 | 用现有 `raven-local-revision` 链路跑 10 个修订任务 × 3 次 |
| 状态页更正 | `docs/development-status.md` 更新为实际注册数与当前优先级 |

**放行条件：** E1 报告完成；现状 pass^3 与调用数有实测；失败归因表能把每次失败归到第四节的一类。

**转向条件：** 若口播场景卡在 E1 中 Oracle 与 None 持平，先改写卡片内容，再做接口工作。

## 阶段 1：收窄与纵切（离线验证）

| 交付 | 说明 |
| --- | --- |
| 数据契约 | `task-spec/1`、`evidence-record/1`、`edit-intent/1`、`write-receipt/1` 定稿 v1 |
| 写入通道 | `edit.propose` / `edit.commit`；修改编号与意图摘要；读回三级 |
| 工具组 v1 | `work.*`、`media.*`、`transcript.*`、`edit.*`、`render.*`、`review.*`，以及最小的 `style.*` |
| 入口瘦身 | 入口 Skill 只含硬规则与工具组摘要；`router.md` 拆进场景卡与方法卡 |
| 活跃场景卡 | `raven-speech-edit`、`raven-local-revision` |
| 接点真值 | `zh-cut-truth` 首批 60 段，及 `cut-point-snap`、`breath-policy`、`room-tone-fill` |
| 程序硬门 | B0、合规门、中文排版门 |
| 风格最小集 | 1 个设计系统族的 3 个包装包；规格表、引语大字、关键词强调等约 6 个组件；B1-P 与 B1-A 复跑脚本 |
| 实验 | E2、E3、E5（两张卡）、E6 预试验与正式评测、E7 |
| 偏好事件 | 开始记录（已定的同意规则） |

**放行条件：**

- 局部修订的写入相关调用不超过 4 次；锁定对象的 pass^3 不低于 95%；重复写入为 0。
- 瘦身后的路由在 E3 中不比长路由低 3 个百分点以上。
- 至少 1 个包装包按修订后的 G2 胜过 B1-P，并且不输 B1-A。
- E7 给出评审器一致率；未达标时评审器只出观察，不参与放行。
- 规格表“只改第二处”的局部修改例在冷开与导出后通过。

**放弃或转向条件：**

- E2 中组合入口既不提升 pass^3 10 个百分点以上、也不减少 30% 以上调用：保留原子直调，但运行时仍持有哈希与版本。
- E6 中包装包普遍输给 B1-A：停止扩包，改走“少量方法卡 + 通用 Agent + 好工具”路线，风格包只保留品牌与系列锁定用途。
- E5 中某张场景卡无正效应或出现负迁移：改写或退役，不进入阶段 2。

## 阶段 2：取证层与宿主接入（外部接入）

| 交付 | 说明 |
| --- | --- |
| 取证层 | 只读子代理配置与提示模板；`evidence.search` 与素材索引；E4 |
| 宿主一致性测试 | 由影述合同测试改写，在剪辑 Agent 上运行 |
| 宿主接入 | I0–I5 按研究库任务卡实现；工具组后端切到宿主；剪辑 Agent 工程为唯一权威 |
| 活跃场景卡 | 增加 `raven-commerce-story`（主张—证据表可程序核对） |
| 短剧接入 | `gen.*` 工具组（`preflight`、分批 `submit`、`status`、账本、`adopt`）；`drama-post-handoff/1` 导入；一次补镜往返；E8、E9 |
| 风格扩展 | 只扩过了 G2 的家族；第二批组件按家族需要补 |

**放行条件：** 宿主一致性测试全部通过；同一工程内多风格预演、采用、撤回、冷开、导出读回一致；E4 报告；一次补镜候选被局部采用且其余时间线不变。

**转向条件：** 宿主无法提供操作号幂等或基准修订校验时，阶段 2 只开放预演，不开放提交；E4 中动态委派不胜过同预算多次时，取证只用固定流程并行。

## 阶段 3：应用内置与按证据扩张

| 交付 | 说明 |
| --- | --- |
| 界面 | 场景卡入口（指定组路由）、方向对照、属性面板、版本面板读回执 |
| 记忆 | 风格记忆（品牌、系列、个人），只记录已采用版本 |
| 校准 | 用偏好事件与 E1 数据校准风格路由权重与场景卡描述；可尝试自动提示优化，目标函数为指定组与自选组的差距 |
| 扩张 | 只有过了门的家族进入货架；机制包（遮罩、跟踪、转绘）单独立项验收 |
| 回归 | 每次模型升级跑 E10，退役多余资产 |

**放行条件：** 多风格方案 C 阶段的条件，加上货架上每个包都有按聚类口径的评测记录。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 冻结让外部看起来进展变慢 | 阶段 0 的实测报告本身就是对外可展示的成果；分享文章已公开这套方法 |
| 工具组改名影响现有用户 | `run_operation` 保留；`list_skills` 标注内部与可见；变更写入 CHANGELOG |
| 评审池组织不起来，G2 无法执行 | 阶段 1 先用剪辑师 3–5 人加内部观众做预试验，估 ICC；正式门槛等评审池到位 |
| 宿主接入后出现两份权威状态 | 合同只在宿主实现；影述 Work 只在离线与本地 CLI 使用 |
| 实验成本超预算 | 每个实验预注册预算上限；E1、E3 先在路由层跑，不做端到端 |
| 模型升级让一部分资产失效 | E10 定期退役，状态阶梯里保留 `retired` |
