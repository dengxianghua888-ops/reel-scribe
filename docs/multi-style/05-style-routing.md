# 03 风格路由：从任务背景和素材，得出“适合哪几种风格”

## 一、路由分三级，风格路由是最后一级

| 级别 | 问题 | 负责者 | 输出 |
|---|---|---|---|
| 场景路由 | 这是口播、解说、教程、商品还是短剧？ | 现有 [router.md](../../registry/router.md)（Agent 语义分派） | 场景工作流，如 `raven-speech-edit` |
| 生产路线 | 用已有素材剪、需要生成、混合，还是只出方案？ | 新增路线判定（§三） | `EDIT / GENERATE / HYBRID / PLAN` 与返工单位 |
| 风格路由 | 在可行路线里，哪几个风格包适合这批素材和目标？ | 新增 `style-route`（§四–§七） | 3 个有差异的方向＋证据＋代价 |

风格路由不改变场景判断：一条口播即使选了“杂志专访”包，仍按口播工作流保护原意。混合片可以按段落分别路由（§八）。

## 二、输入：意图与画像

### 1. StyleIntent：把用户的风格说法记成约束

用户的话分四类处理，每条都记录原话、解析结果和来源（原话 / 上下文 / 推断）：

| 说法类型 | 例子 | 解析为 | 处理 |
|---|---|---|---|
| 点名风格包 | “用红黑参数风” | `pack_id` 指定 | 仍跑资格与适配；适配低时提示风险并附一个替代方向 |
| 风格形容词 | “科技感”“高级”“温暖”“犀利” | 刻面约束集合（见下表） | 不直接映射为参数；作为打分偏置并进入预览对照 |
| 参考片 | “做成这条那样” | 参考画像，经 `raven-reference-style` 拆维度 | 每个维度单独决定采纳 / 调整 / 舍弃，不整包照抄 |
| 否定与冻结 | “别太花”“字幕以外别动”“不要音乐” | 硬约束或密度上限 | 优先级高于风格包默认值 |

风格形容词的首版解析表（可扩展，均为偏置而非结论）：

| 说法 | 偏向的刻面 | 抑制的刻面 | 必须预览确认的点 |
|---|---|---|---|
| 科技感 | 设计系统族“技术图解与数据看板”“几何空间与留白”；组件 `spec-table`、`data-callout`；节奏中快 | 手写、柔和水彩 | 数据图形是否与当前说到的值同步 |
| 高级 / 质感 | 克制密度；几何留白或杂志版式；影调低饱和、高光滚降；声音少而准 | 大字冲击、每句花字 | 没有唯一参数，必须两到三版对照 |
| 温暖 / 亲切 | 方法“自然陪伴”；手写批注族；影调偏暖；Lo-fi 底声 | 硬切快剪、冷色看板 | 不能把思考停顿当故障删掉 |
| 犀利 / 有观点 | 方法“紧凑观点”；大字引言族；节奏快、主张前置 | 长铺垫 | 不得剪掉限定制造绝对化 |
| 纪录感 | 方法“证据解释”；新闻杂志版式；影调自然；环境声主导 | 霓虹、过度包装 | 来源与重现要可区分 |
| 综艺感 | 大字花字、音效点缀；节奏快 | 留白 | 音效不压人声；笑点不抢解释 |

### 2. MaterialProfile：带证据的素材画像

画像的每个特征都有 `value`、`evidence`（词 ID、源时间区间或帧号）、`source`（`deterministic` / `model-observation` / `user-declared`）与 `confidence`。模型观察只作候选，不冒充已听检结论。Schema 见 [material-profile.schema.json](schemas/material-profile.schema.json)，样例见 [examples/material-profile.phone-review.json](examples/material-profile.phone-review.json)。

| 特征组 | 特征 | 计算方式 | 复用 / 新增 |
|---|---|---|---|
| 源与规格 | 时长、画幅、帧率、声道、是否 HDR/Log | 确定性 | `media-inspect` |
| 语言 | 词数、语速、停顿分布、重录与假起头候选、说话人数 | 确定性＋模型 | `transcript-import`、`speech-transcribe-local` |
| 内容信号 | 数值与单位、规格对、列表项、步骤、引语、比较、转折、问题、主张、例子、故事节拍、情绪峰、幽默点、商品提及、章节边界、强调词 | 正则（数值单位）＋模型标注（其余），全部落到词 ID 区间 | 新增 `content-signal-extract` |
| 结构 | 观点→论据→例子→条件→结论图；章节；论证密度 | 模型，复用口播工作流的结构读法 | 新增（并入上项） |
| 画面 | 人脸 / 主体框与安全区、景别分布、背景复杂度、可放图形的空区、B-roll 可用量 | 检测＋确定性 | 新增 `subject-safe-zone-detect`；`frame-extract` |
| 色彩 | 影调分位、色温倾向、饱和度、肤色区 | 确定性 | `color-profile-scan` |
| 能量 | 画面变化率、音频能量、音乐是否存在、节拍 | 确定性 | `media-signal-scan`；新增 `beat-detect` |
| 上下文 | 平台、受众、品牌色与字体、系列锁定、历史采用的风格包 | 用户声明＋风格记忆 | 新增 `style-memory` |

**派生指标**（路由直接使用，均可由上表复算）：`numeric_density_per_min`、`step_count`、`quote_count`、`story_ratio`（叙事句占比）、`argument_ratio`、`emotion_arousal_mean/peak`、`humor_density`、`face_center_ratio`（人脸位于中央的时长占比，影响版位）、`free_side`（画面左右哪侧空）、`broll_minutes`、`speech_rate_cps`、`pause_ratio`。

## 三、生产路线判定

| 条件 | 路线 | 返工单位（入口必须告诉用户） |
|---|---|---|
| 有可用原片且目标是整理、包装、改结构 | `EDIT` | 切点、字幕行、组件实例、调色层、音轨，均可局部改 |
| 只有图片 / 商品图 / 剧本，需要新镜头 | `GENERATE` | 单个生成镜头；片内手势、口型、商品形态通常要重生成 |
| 有部分原片，缺少插入镜或演示 | `HYBRID` | 原片部分同 EDIT；生成插入镜同 GENERATE；两者分别登记 |
| 只要分析、脚本、分镜、方案 | `PLAN` | 文本；不启动渲染与生成 |

路线判定先于风格路由。用户说“做成种草风”而只给商品图时，系统先说明“这会生成一段人物演示，片内动作要改需重生成”，再比较生成类风格包。

## 四、第一步：资格过滤（硬条件）

逐包检查，结果为 `eligible`、`eligible-degraded`（可做但有刻面降级）或 `ineligible`，每项都附原因：

1. **路线匹配**：包声明的 `routes` 包含本次路线。
2. **能力可用**：包的 `capability_requirements` 中 `required` 项在当前宿主或本库运行时实查可用；`optional` 缺失则按包声明的降级方案转 `eligible-degraded`。遵循[能力交接合同](../../contracts/capability-handoff.md)，本库实现缺失不等于宿主不可用。
3. **素材前提**：包的 `requires_signals` 与 `requires_assets` 满足。例：Monochrome 杂志包需要主体分割；规格看板包需要至少一个数值信号；B-roll 转手绘包需要可用 B-roll。
4. **平台与画幅**：设计系统在目标画幅有版位定义。
5. **品牌与授权**：字体、音乐、贴纸素材的授权可用；品牌锁定的颜色与包的设计系统可兼容或可覆写。
6. **保护项冲突**：包的默认行为不会触碰已登记的保护项（例如强制删停顿的节奏包遇到“保留情绪停顿”的保护）。
7. **用户排除**：被用户否定过的刻面（“不要音乐”）不能是包的必需项。

## 五、第二步：适配打分（软条件）

每个风格包在 `fit` 中声明正信号与反信号谓词，形如：

```json
{"signal": "derived.numeric_density_per_min", "op": ">=", "value": 1.5, "weight": 0.30, "why": "参数足够多，看板才有内容可亮"}
{"signal": "derived.story_ratio", "op": ">=", "value": 0.5, "weight": -0.35, "why": "以个人经历为主时，规格表会抢走情绪"}
```

总分（每项归一到 0–1 后加权，权重可调，首版取值见括号）：

```
S(p) = 0.40·Fit_signals(p)          # 包声明的正反信号
     + 0.15·Goal(p)                 # 与观众任务/交付目标的一致度（教学、说服、陪伴、种草、留档）
     + 0.10·Intent(p)               # 与 StyleIntent 偏置的一致度
     + 0.10·Brand(p)                # 品牌色 ΔE2000 距离、字体兼容、调性
     + 0.10·Series(p)               # 系列已有风格时的一致性奖励；新系列则改为探索奖励
     + 0.10·Tier(p)                 # 验证等级：validated > limited-trial > previewed > compiled > authored
     − 0.10·Cost(p)                 # 生成镜头数、机制刻面数、预估返工
     − Penalty_cliche(p, profile)   # 命中俗套且无正当理由时扣分，见 09 章
```

两点约束：

- **Fit 低于 0.35 的包不进入候选**，避免“为了凑三个方向推荐不合适的风格”。
- **打分可复算**：谓词计算由确定性程序完成；模型只负责产出画像中的语义信号（带证据）。Agent 可以推翻排序，但必须在路由记录里写理由。

## 六、第三步：多样性选取（稳妥 / 特色 / 反差）

每个包投影为一个**风格向量**：离散部分为方法族、设计系统族、字幕类型、声音类型的 one-hot；连续部分为 7 个轴（0–1）：

| 轴 | 0 端 | 1 端 |
|---|---|---|
| tempo 节奏 | 舒缓留白 | 紧凑快切 |
| density 包装密度 | 几乎无图形 | 高频图形 |
| ornament 装饰度 | 极简 | 繁复肌理 |
| warmth 温度 | 冷 | 暖 |
| contrast 对比 | 柔和 | 强烈 |
| formality 正式度 | 闲聊 | 正式报告 |
| motion 运动强度 | 静态 | 强动效 |

两个包的相似度同时看连续轴与离散刻面（不用余弦：7 个轴都在 0–1 内，余弦会把几乎所有包算成高度相似）：

```
sim(a, b) = 0.6 · (1 − ‖v_a − v_b‖₂ / √7)  +  0.4 · share(a, b)
share(a, b) = 方法、设计系统、字幕样式、声音四个刻面中，引用完全相同的比例
```

用最大边际相关（MMR）依次挑选：

```
第 1 个（稳妥）：argmax S(p)
第 2 个（特色）：argmax [ 0.6·S(p) + 0.4·Signature(p) − 0.5·sim(p, 已选) ]，且 S(p) ≥ 0.55
第 3 个（反差）：argmax [ 0.5·S(p) − 0.8·sim(p, 已选) ]，且 S(p) ≥ 0.45，必须写出“为什么反着来对这条素材有意义”
```

`Signature(p)` 来自包声明的签名手法强度（见 09 章），用来对抗“平均最优”：最高分的包往往最安全也最普通，第二个方向专门留给“有辨识度且仍然合适”的选择。三个方向的风格向量两两相似度应低于 0.8，否则从候选池补位并说明“当前素材可选风格较窄”。

## 七、第四步：解释、预览与选择

### 1. 每个方向的解释模板

> **方向 B · 特色：Spec Redline（红黑参数看板）**
> 因为素材在 02:10–05:40 连续讲了 9 个参数（词 w412–w1180，含“续航 12 小时”“重量 187 克”），这个包会在每次说到参数时点亮规格表的对应行，让观众听到数字的同时看清单位。
> 人脸位于画面左侧 62% 时长，规格表放右侧不遮脸。
> 代价：开头 40 秒的个人感受段没有参数，包会降为字幕强调；需要 `mg-component-render`，当前可用。
> 与方向 A 的区别：A 用大字强调观点，B 用表格强调数据。

### 2. 预览分级（在昂贵步骤之前选）

| 级别 | 内容 | 成本 | 用于 |
|---|---|---|---|
| T0 方案对照 | 三个方向的 StylePlan 摘要：哪些词触发什么组件、节奏变化、字幕样式、影调与声音 | 无渲染 | 先排除明显不合适的方向 |
| T1 风格帧 | 每个方向在 3 个代表时刻（开头、信号最密处、情绪峰）用真实帧合成静帧 | 3 帧 × 方向 | 选视觉方向；检查遮脸与可读性 |
| T2 样段 | 每个方向 10–15 秒真实样段（含声音） | 低 | 选节奏与声音；`style-recipe-preview` 的扩展 |
| T3 全片 | 选定方向渲染全片 | 正常 | 验收 |

生成路线的 T1 是风格帧图像、T2 是单个样镜，付费提交前必须过 T1。

### 3. 选择与反馈

用户可以选一个、组合（“B 的看板＋A 的节奏”，由编译器检查刻面兼容）、或要求换向。反馈按维度记录（`readability / occlusion / style-fit / pacing / sound / signature`），绑定推荐结果摘要与 Work 版本，沿用 `creation-recommendation` 的 feedback 规则：反馈不自动成为长期偏好，只有采用后的版本才写入风格记忆。

## 八、段落级路由与临时组合

**段落级路由。** 一条测评可能前 2 分钟谈感受、中间 4 分钟讲参数、最后 1 分钟给结论。允许按章节边界给不同段落选不同的**方法与组件**，但设计系统、字幕样式、影调在全片保持一致（“全片不变量”）；段落切换处由包声明的过渡规则处理。

**临时组合包。** 当所有包的 Fit 都低于 0.5 时，路由可以从刻面空间组合一个临时包：方法（按目标）× 节奏（按语速与时长预算）× 设计系统族（按 StyleIntent 与品牌）× 组件（按信号类型），标记 `authored-adhoc`，不得声称已验证。被采用且效果好的临时包，经 09 章的评测后才能沉淀为正式包。

## 九、路由模式

| 模式 | 触发 | 行为 |
|---|---|---|
| 推荐（默认） | 只有 brief 和素材 | 完整四步，给三个方向 |
| 指定 | 用户点名风格包 | 资格＋适配检查；适配低于 0.5 时提示并附一个替代 |
| 系列 | 风格记忆中有本系列锁定包 | 直接沿用锁定包，只在 runtime 槽内适配；用户要求“换个风格”才进入推荐 |
| 参考 | 用户给参考片 | `raven-reference-style` 拆维度，生成“参考派生包”参与打分 |
| 修订 | 已有作品的局部反馈 | 不重新路由；在原包内改 StylePlan，走 `raven-local-revision` |
| 批量变体 | “同一素材出三版风格” | 推荐模式取三个方向，各自派生 `work-variant-create` 版本，保护父版 |

## 十、对 router.md 的增补建议

在现有“显式包装配方与修改影响”一节之后增加“风格选择与多风格对照”：

- 含“风格、调性、像某某、做几版不同风格”的请求，在场景工作流内调用 `style-route`；明确字段参数（“字幕 42 号白色”）仍直接走原子。
- 风格路由只在已判定的生产路线内比较；路线不明时先问交付物或素材起点。
- 风格包不能放宽保护项；风格偏置与保护冲突时，保护优先并在报告中注明。
- “出几版不同风格”使用批量变体模式，每版独立版本，父版保护。
- 路由结果是建议，不自动采用；采用仍需预览、审阅与 `work-version commit`。
