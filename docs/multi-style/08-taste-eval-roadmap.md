# 08 审美门、评测与路线图

## 一、“不平庸”怎样落成可检查的门槛

包装平庸通常不是因为做得少，而是因为**默认值太多**：每句都有花字、每一刀都有转场音、所有数字都放大、音乐从头铺到尾。观众记不住任何一处，因为没有任何一处被选择过。对策分五层：

| 机制 | 要求 | 检查方式 |
|---|---|---|
| 签名手法 | 每个包声明 1 个签名手法（如“只点亮正在讲的那一行”），它必须在成片中出现 ≥3 次、与内容信号绑定、且能被一句话描述 | `style-conformance-check` 计次；盲评问“这条片子的视觉特点是什么”，统计能否说出签名 |
| 克制规则 | 每个包声明 ≥2 条“不做什么”（如“观点句不加图形”“不用弹出动画”） | 规则可测的自动检查；其余进 `taste-review` |
| 强度曲线 | 包装强度随内容起伏：信号密集段与情绪峰最强，过渡段降到最低；全片不允许恒定高强度 | 每 10 秒窗口的组件与音效事件数，峰谷比 ≥ 2 |
| 视觉层级 | 任一时刻画面只有一个第一视觉落点：人脸、组件、或字幕强调三选一 | 同屏组件数；强调色面积占比；`taste-review` 抽帧 |
| 俗套黑名单 | 包声明禁用的俗套；命中而无正当理由时路由扣分、编译告警 | 编译器规则匹配；`taste-review` |

### 剪辑侧俗套清单（首版）

每条都有“何时可以用”，避免教条化：

| ID | 俗套 | 为什么平庸 | 何时可以用 |
|---|---|---|---|
| `every-line-popup` | 每句话都弹花字 | 强调失去意义，遮挡表情 | 综艺式快问快答，且只弹关键词 |
| `random-sfx` | 无触发的音效点缀 | 声音与画面事件无关 | 音效有明确触发（扣合、点亮、翻页） |
| `whoosh-every-cut` | 每一刀配转场音 | 把剪辑痕迹放大成噪声 | 章节切换，且全片 ≤ 章节数 |
| `constant-punch-in` | 全程推近抖动 | 观众疲劳，无重点 | 只在主张或笑点处，每分钟 ≤ 2 次 |
| `rainbow-keywords` | 每屏多色高亮 | 层级混乱 | 设计系统只有一个强调色 |
| `emoji-sprinkle` | 随机贴表情 | 与说话人气质无关 | 说话人本人风格如此，且有系列一致性 |
| `stock-broll-cover` | 用无关空镜盖住讲者 | 削弱可信度 | B-roll 证明或解释正在说的内容 |
| `bgm-wall` | 音乐从头铺满 | 压人声、无起伏 | 音乐片；或口播仅在开头与转场进入 |
| `zoom-every-number` | 每个数字都放大 | 数字失去主次 | 只放大与结论直接相关的数字 |
| `glitch-transition` | 无动机故障转场 | 风格与内容脱钩 | 内容本身关于故障、黑客或时间跳跃 |
| `template-intro` | 通用片头动画 | 与本期无关 | 系列品牌片头，≤ 2 秒 |
| `fake-urgency` | 倒计时、假稀缺 | 误导，且与事实保护冲突 | 不可用（有真实期限时用文字说明） |
| `beauty-blanket` | 全片一刀切美颜 | 塑料感，肤色失真 | 用户明确要求，且保护肤色色相 |
| `subtitle-everything-giant` | 全程巨大字幕 | 抢人脸 | 无声观看场景且画面信息少 |

生成侧（短剧）的俗套清单见短剧仓库方案第 04 章，两边的 ID 不重叠，路由时合并使用。

### 审美评审（`taste-review`）评分表

评审对象是成片联系表（每 2 秒一帧）＋三段 10 秒样段＋包声明。模型评审只出观察与疑点；结论以盲评为准。

| 维度 | 看什么 | 自动代理指标 | 判定者 |
|---|---|---|---|
| 意图一致 | 风格是否服务这条内容的观众任务 | 绑定规则命中的信号类型与方法刻面一致 | 评审 |
| 识别度 | 能否一句话说出风格特征 | 签名手法出现次数 | 盲评 |
| 层级 | 每帧是否只有一个第一落点 | 同屏组件数、强调色占比 | 自动＋评审 |
| 一致性 | 全片是否同一套 tokens、影调是否漂移 | token 合规、`color-consistency-check` | 自动 |
| 节制 | 强度是否随内容起伏 | 峰谷比、密度预算 | 自动 |
| 工艺 | 时机、遮挡、可读、单位 | `value-word-sync`、`face-occlusion`、最小字号、`unit-integrity` | 自动 |

### 默认基线盲测

每个包的 `limited-trial` 与 `validated` 都要求与**默认基线**做盲评对照。默认基线 = 同一剪辑结果 ＋ 通用白色字幕 ＋ 无组件 ＋ 无调色 ＋ 无音乐。若风格包在盲评中不能稳定胜过基线（偏好率 < 60%），说明它在增加噪声而不是增加信息，不得升级状态。这条规则直接对抗“包装越多越好”。

## 二、评测体系

### 1. 五层指标

| 层 | 指标 | 定义 |
|---|---|---|
| 路由 | Top-3 可接受率 | 专家标注“可接受的包”集合与三个方向的交集非空的比例 |
| 路由 | 方向差异度 | 三个方向风格向量的平均两两距离；< 0.2 视为同质 |
| 路由 | 解释有效率 | 解释中引用的证据（词 ID、时间）可回查且支持结论的比例 |
| 编译 | 编译确定性 | 同输入重复编译字节一致 |
| 编译 | 保护违例 | 风格编译触碰保护项的次数；硬门为 0 |
| 一致性 | 检查通过率 | 包声明检查项的通过比例 |
| 一致性 | 局部改成功率 | “只改第二处”类修改不影响非目标对象的比例 |
| 审美 | 胜基线率 | 盲评中风格版本胜过默认基线的比例 |
| 审美 | 签名识别率 | 看完能说出签名手法的评审比例 |
| 审美 | 包间可区分率 | 同素材两包的盲评中，评审能正确指出哪版属于哪种描述 |
| 结果 | 首选采纳率 | 用户在三个方向中直接采用某一个、不要求换向的比例 |
| 结果 | 返工分钟 | 从候选到可发表所需人工修改时间 |
| 结果 | 系列复用率 | 下一期沿用同一包的比例；风格漂移投诉数 |

### 2. 评测集

| 集合 | 规模 | 内容 |
|---|---|---|
| 口播 | 20 条真实中文口播 | 测评、知识、观点、经历、教学各 4 条；时长 1–15 分钟 |
| 商品实拍 | 10 组 | 每组同一商品的开箱、操作、结果、标签；含 2 组外形相近的易混 SKU |
| 剧情场次 | 5 场 | 对白、对峙、物证揭示、群像、亲密各 1 场（与短剧仓库共用） |
| 路由标注 | 每条素材 | 2 名标注者独立给出“可接受包集合”，分歧单列 |

所有结果按库内口径登记：技术、内容、完整看听、编辑器工程、独立评审分别记录；没有证据的维度保持 `not-run`。

## 三、路线图

与研究库[口播与带货建设判断](https://github.com/dengxianghua888-ops/editing-agent-research-library/blob/92b600d605b8bd8ed0e2c938c13561d3e66276e7/library-sync/followups/20261126-chatcut/2026-11-26-chatcut-0.10.14/%E8%87%AA%E7%A0%94%E6%98%A0%E5%B0%84/%E5%8F%A3%E6%92%AD%E4%B8%8E%E5%B8%A6%E8%B4%A7%E5%BB%BA%E8%AE%BE%E5%88%A4%E6%96%AD.md)的顺序对齐：先口播精剪与实拍单品，静态规格卡是两者共用的第一个包装模板，动态高亮与生成在后。

### 第一期（P0）：一套流水线挂三套皮肤

| 工作项 | 产出 |
|---|---|
| Schema 与注册表 | 本目录 schemas 定稿为 v1；`packs/`、`facets/` 目录与结构检查 |
| 画像 | `content-signal-extract`（数值规则＋模型观察）、`subject-safe-zone-detect`（人脸）、`material-profile-build` |
| 风格层 | `style-route` v0、`design-token-resolve`、`style-pack-compile` |
| 组件 | 规格表、数值标注、引语大字、荧光划线 4 个组件，先走静态 `visual-layer-render` 降级路径 |
| 风格包 | `speech-packaging-base` ＋ 3 个皮肤包（红黑参数看板、观点大字、陪伴手记）；3 套原创设计系统 |
| 预览与检查 | `multi-style-preview` T0–T2；`style-conformance-check` |
| 生成侧 | 剧本画像、方向卡、风格圣经模板、俗套清单、风格帧协议（见短剧仓库方案） |
| 交接 | `drama-post-handoff/1` 草案，用登记桌 15 秒试拍素材导入一次 |

**放行条件**：3 条真实中文口播 × 3 个包全部编译、预览；保护违例 0；同一规格表放两次只改第二处的局部修改例通过（冷开、导出复核）；每条素材的三个方向两两相似度 < 0.8；与默认基线的盲评有记录（不要求胜出，第二期才设门槛）。

### 第二期（P1）：动起来、能记住、接上商品

| 工作项 | 产出 |
|---|---|
| 渲染 | `mg-component-render`（HTML 模板、固定无头浏览器版本）、`caption-animate`、`sound-event-place` |
| 质量 | `taste-review`、俗套检测、强度曲线检查 |
| 记忆 | `style-memory`：品牌、系列、个人三种作用域 |
| 扩充 | 设计系统扩到 6 套（覆盖 6 类视觉语言），组件扩到 10 个；口播皮肤包扩到 6 个 |
| 商品 | 3 个商品实拍包（操作作证、物声 ASMR、先讲限制），全部读取主张—证据表 |
| 生成侧 | 提示词模块编译器、一场戏三方向风格帧试验、补镜往返一次 |

**放行条件**：10 条口播、5 组商品上，至少 2 个包达到 `limited-trial`；胜基线率 ≥ 60%；局部改成功率 ≥ 95%；系列复用试验（同一系列连续 3 期）风格漂移投诉为 0。

### 第三期（P2）：机制包与开放组合

| 工作项 | 产出 |
|---|---|
| 机制 | `subject-matte`、`object-track`、`style-transfer-window`、`layer-compose`；杂志分层、线框实物、真人转手绘三个机制包 |
| 音乐 | `beat-detect` 与音乐驱动节奏包 |
| 参考 | 参考片 → 参考派生包（`raven-reference-style` 输出包草案） |
| 入口 | 入口模板目录：样片、素材角色槽、交付物与返工单位 |
| 开放组合 | 临时组合包的沉淀流程：被采用 ≥3 次且盲评达标即可转正 |

**放行条件**：机制包各自通过能力验收与风格验收；评测集全量跑通；货架只展示 `limited-trial` 以上的包。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 结构化过度，扼杀判断 | 语义选择、信号解释、方向理由都留在 runtime 槽由 Agent 判断；临时组合包保留探索空间 |
| 模型信号出错导致组件放错 | 信号带证据与置信度；低置信信号不触发高优先级组件；预览门把关 |
| 模板化导致千篇一律 | 签名手法、强度曲线、旋钮；同基础包皮肤相似度上限；系列内锁定、系列间鼓励探索 |
| 字体与音乐授权 | 字体按哈希绑定并记录许可；音乐库只收可商用来源，授权进入资格过滤 |
| 宿主差异 | 全部能力按能力交接合同映射；宿主无读回时标 `not-verifiable` |
| 风格掩盖事实错误 | 事实保护在风格层之上；主张—证据表跨包共享；生成演示不能作证据 |

## 五、需要你拍板的决定

1. **首批三个皮肤包**是否就用“红黑参数看板 / 观点大字 / 陪伴手记”，还是换成你更常做的题材？
2. **组件模板引擎**选 HTML/CSS 逐帧渲染（排版能力强，依赖固定版本无头浏览器）还是 ASS（轻、文字类够用、图形弱）？建议 HTML 为主、ASS 为文字类快速路径。
3. **路由权重**首版按本方案的默认值，是否需要按你的业务（例如更看重品牌一致还是探索）调整？
4. **生成侧的第一个三方向试验**用《青锋有痕》以外的新剧本，还是用《青锋有痕》的番外或预告（正片画风已锁定）？
