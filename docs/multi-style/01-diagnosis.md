# 01 诊断：ChatCut 怎样把“风格”做成产品，两仓还缺哪几层

本章只做事实归纳和差距判断。ChatCut 的数字均来自研究库 2026-11-26 的 0.10.14 桌面包、账号目录与网站快照，口径见[风格拆解](https://github.com/dengxianghua888-ops/editing-agent-research-library/blob/92b600d605b8bd8ed0e2c938c13561d3e66276e7/library-sync/followups/20261126-chatcut/2026-11-26-chatcut-0.10.14/%E7%9C%9F%E4%BA%BA%E5%8F%A3%E6%92%AD%E4%B8%8E%E5%B8%A6%E8%B4%A7%E9%A3%8E%E6%A0%BC%E6%8B%86%E8%A7%A3.md)；推论部分会标明“推论”。

## 一、ChatCut 的风格体系：十个可借鉴的机制

### 1. 入口先按“手里有什么素材”分流

账号可见 212 个官方工作流，按执行动作分为 97 个 Agent 表单、41 个视频生成、18 个图片生成、56 个只有制作指南。用户在首页选卡时，同时选了“交什么素材、谁来执行、拿到什么”。真人口播卡进入本地编辑工程；商品生成卡提交一次可跟踪的生成任务；直播切片指南交给 Agent 读取长素材后自行编排。

**对我们的含义。** 风格选择不能是第一个问题。先确定生产路线（剪辑 / 生成 / 混合 / 只出方案），风格只在路线内部比较；否则会把“真人原片的口播”和“生成人物的种草视频”放在同一个风格下拉框里，返工成本完全不同却看起来一样。

### 2. 卡片是一组被预先做掉的决定

Redline Tech 选卡即锁定“参数用黑底表格、红行强调”，而“哪句话出现参数、什么单位、表格何时退出”要等 Agent 读完词稿再定。ASMR 开箱选卡即锁定“窗边近景、手部动作、包装声、图 1 绑商品图 2 绑人物”，商品名称、外形、卖点在提交时才替换。

**对我们的含义。** 风格包要显式声明三类决策槽：选包即定（locked）、读素材再定（runtime）、必须问用户（user）。这条分界决定 Agent 的自由度，也决定用户换风格后哪些东西会变。

### 3. 八成“新风格”只是换皮

11 张口播包装中，8 张从第一个编号步骤到文末逐字相同，只替换卡名和 UUID；标准化后每份 2,352 字符、SHA-256 相同，表单把 `designStyleId` 限定为各自一个值。另 3 张（Wireframe、Monochrome Magazine、Real Footage to Handpainted）分别增加组件脚本、三层合成模板或转绘程序。

**对我们的含义。** 风格扩充有两条成本差异巨大的路线：**皮肤**（同一剪法 × 不同设计系统，近乎零边际成本）与**机制**（新增物体识别、遮罩、转绘等能力）。路线图应先把皮肤机制做扎实，让一套流水线能挂多套设计系统；机制包按需逐个立项。

### 4. 设计系统与剪法分离存储

54 个 Design Style 按视觉语言分为 7 类：手写笔记与批注 9、剪纸拼贴与套色印刷 11、人物新闻杂志版式 10、大字引言与字形动画 9、技术图解与数据看板 5、几何空间与留白 4、渐变材质与光效 6。设计风格保存为项目偏好，指导后续生成的动效；切换项目风格不会自动重做已生成的图层。

**对我们的含义。** 需要一个独立的“设计系统”注册表，内容是颜色角色、字体字阶、版位、运动曲线和质感，而不是叙事判断。它可以跨工作流复用（口播、教程、商品都能用“技术看板”），也可以被品牌覆写。

### 5. 组件实例可以单独改值，但组件储备不均

桌面代码按实例 ID 查资产声明过的属性，核对类型、数值范围或枚举，再写这一实例的覆盖值；同一组件在时间线出现两次可以各改各的。读取三份风格详情时，Runway Rebel 直接关联 7 个具名组件，Redline Tech 与 Highlight Moments 均为 0，只有设计规范和继续搜索实例的指引。

**对我们的含义。** “有设计规范”与“有可直接取用、可局部改的组件”是两回事。组件要声明可编辑属性、默认值、时间锚点和版位约束；验收例就是研究库提出的“同一规格卡放两次，只把第二处从 500 g 改成 0.5 kg”。

### 6. 生成卡的差异藏在参考角色和拍法里

14 张商品 UGC 卡都调用同一个视频工作流动作，12 张各带一份独立的生成改写指令（指纹全不同）。自拍推荐让图 1 控制人物、图 2 控制商品；窗边 ASMR 反过来。13 张品牌 TVC 中 10 张连通用改写指令都相同，创意差异放在案例说明与素材角色里。

**对我们的含义。** 生成类风格 = 执行器（共用）× 参考角色槽（按角色绑定，不按顺序）× 拍法指令（每风格一份）× 案例库。短剧 Skill 的“每个引用标职责”已经是这个思路，需要结构化。

### 7. 开放式创作靠“结构工具箱 × 品类案例”组合

桌面内置 `ugc-ad-guide` 把商品知识、成熟结构和可变镜头分开：创意工具箱列 6 种开头、4 类证明、5 类收尾；11 个品类参考文件有 50 个脚本案例，同一音箱既可拍无旁白 ASMR，也可从桌面痛点讲起。

**对我们的含义。** 风格不必全部预制成卡。“钩子 × 证明 × 收尾 × 视觉处理”的组合空间，加上路由打分，可以在运行时生成风格方向，再沉淀高分组合为正式包。

### 8. 事实错误不能靠换风格修

直播切片指南要求一条只讲一款商品，证明镜头必须属于同款，过期促销要处理，同商品多版本须在开头、证据或顺序上实质不同。这个场景最贵的错误是把 A 款的价格或效果剪给 B 款，换动效包解决不了。

**对我们的含义。** 风格层永远在事实与保护层之下。影述已有的 `evidence_protection`、主张与证据计划应成为所有风格包的硬约束。

### 9. 用户认可的做法可以沉淀

桌面 `skill-creator` 指南要求记录触发条件、稳定输入、用户认可的节奏和偏好、工作步骤与检查项。

**对我们的含义。** 需要“风格记忆”：品牌、系列、个人的已采纳风格包与微调，跨片复用，而不是每期重新问。

### 10. ChatCut 自己的缺口就是我们的机会

研究确认：外部 MCP 未见按官方卡 ID 原样启动整套工作流并返回同一运行 ID 的通用入口；组件储备不均；公开商品接口不能表达“每条主张绑定哪段源帧、何时失效”；没有对同一素材横测风格的公开机制。这四处恰好是影述强项（可追溯合同、局部修改、证据绑定、候选对照）可以超越的地方。

## 二、抽象出来的“风格”模型

ChatCut 中“风格”至少有五个作用范围（[0.10.12 产品拆解 §4](https://github.com/dengxianghua888-ops/editing-agent-research-library/blob/92b600d605b8bd8ed0e2c938c13561d3e66276e7/library-sync/followups/20261126-chatcut/2026-11-25-chatcut-0.10.12/%E4%BA%A7%E5%93%81%E5%88%86%E6%9E%90/ChatCut%E4%BA%A7%E5%93%81%E6%8B%86%E8%A7%A3.md)）：Design Style（品牌与视觉规范）、Caption Style（字幕，跨端 49 款）、包装 Skill＋设计风格＋MG 组件（在哪句话放哪种信息）、镜头级调色与 Film Look（像素影调）、场景／样片 Skill（拍法、表演、材质、画幅、声音）。归纳为一个公式：

> **作品风格 = 制作路线 ×（剪辑方法 × 节奏）×（设计系统 × 组件 × 字幕）× 影调 × 声音 ×（生成处理 × 参考角色）**，再受事实保护与平台规格约束。

每个因子都应能单独替换、单独验收。下一章把它落成刻面与风格包。

## 三、影述现状：强在“可信执行”，弱在“风格装配”

| 已有资产 | 规模 / 状态 | 对多风格目标的意义 |
|---|---|---|
| 场景工作流 | 17 条，覆盖口播、解说、短剧、教程、访谈、Vlog、商品、音乐、本地化等 | 可直接作为“剪辑方法”的执行骨架 |
| 原子操作 | 注册 51 个原子＋1 个适配器；口播逐词计划、字幕、混音、包络、调色、Log/HDR 转换、胶片质感、版本、局部撤销、变体与批量渲染 | 调色与质感链已很强，可直接组成“影调刻面” |
| 风格卡 | 16 个领域 580 张，字段为适用、观众问题、选段、结构、声音、节奏、字幕画面、反例、相邻差异、效果检查；全部 `authored-unvalidated` | 本质是**剪辑与叙事方法**，不是视觉风格 |
| 风格配方 `style-recipe/1` | 只能改全局字幕字号/边距/颜色、单条字幕覆盖、音轨增益、音轨包络、调色层 | 呈现层太窄，表达不了“参数表随说话点亮” |
| 创作建议 `creation-recommendation` | 规则化，仅生成字幕字号 1×/1.2×/1.4× 比较假设和教程校验建议；明确声明未对 580 卡逐一语义评分 | 还没有真正的风格路由 |
| 视觉叠层 `visual-layer-render` | 显式静态矩形视频叠层 | 没有参数化动效组件、关键帧和实例改值 |
| 合同体系 | 候选→预览→提交、范围授权、保护项、读回、能力交接 | 是风格系统可以放心扩张的地基 |

**差距清单（剪辑侧）**

| 编号 | 缺口 | 后果 |
|---|---|---|
| G1 | 没有“风格包”这一组合对象，方法卡、字幕、调色、声音各自零散 | Agent 每次临场拼装，不可复现，不可比较 |
| G2 | 没有视觉设计系统（颜色角色、字阶、版位、运动曲线、质感） | “大字观点”“技术看板”“手账荧光”无法落地 |
| G3 | 没有参数化组件库与实例覆盖 | 无法做参数卡、引语大字、章节页，也无法“只改第二处” |
| G4 | 没有素材画像与内容信号（数值、步骤、引语、转折、情绪峰、人脸安全区） | 风格无法“读完素材再决定在哪个词出现” |
| G5 | 没有风格路由（资格、适配、多样性、解释） | 只能靠用户点名或 Agent 凭感觉 |
| G6 | 方法卡是散文，没有结构化的适配信号与反信号 | 580 张卡无法被程序检索和打分 |
| G7 | 同素材多风格对照只覆盖字幕参数（`style-recipe-preview`） | 无法横测“观点大字 vs 参数看板”这种整包差异 |
| G8 | 没有审美门与俗套检测 | 容易产出“每句花字、随机音效”的平庸包装 |
| G9 | 没有风格记忆（品牌、系列、个人） | 系列内容每期重选，风格漂移 |

## 五、两仓之间的缺口

- **没有共享风格词汇。** 短剧 Skill 写“半写实三维国漫、主光从画左门缝进”，影述调色层写 `ops/strength/targets`，两边没有共同的“影调刻面”对象，后期无法按前期意图统一影调。
- **W17 与精品短剧 Skill 职责重叠。** 影述 W17 有宿主中立的剧情合同、状态与修改影响；精品短剧 Skill 有即梦执行与选片。需要划界：前者管作品身份与修订，后者管导演与生成。
- **没有双向交接。** 剪辑时发现缺一个插入镜，没有标准“补镜请求”回到生成侧；生成侧选好的候选与剪辑表，也没有标准格式进入影述 Work。
