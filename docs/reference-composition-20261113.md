# 两参考、两维显式组合

这次推进“分维度融合”，不是继续增加字号候选或新风格卡。仅将两个既有机制按明确顺序组合：独立参考 A 的结果先行信息顺序，独立参考 B 的字幕呈现；目标仍使用自身素材和文字。

## 最小实现

`reference-transfer-prepare` 保持原单参考最多一个机制的行为，另以 `composition: result-first-then-caption` 明确选择编译模式。只支持软件场景、各一个已观察 adapt 项、两个不同媒体摘要、显式字幕变体 ID 和显式 final_scope。

第一阶段调用既有结果预览编译器，保完整原流程与持久保护；第二阶段在该确切中间文档初始化临时 Work，重新验证参考/字幕简报和全部新片段位置，再编译选定的全局字幕参数。第二阶段不能改正文、时轴、镜头、声音、备注或证据保护。最终以原 Work 文档/版本及调用者 final_scope 重验，不自动合并范围、不提交原头。受保护作品最终范围必须再次明确 evidence_mapping，不借第一阶段的授权默认为最终授权。

交付为普通候选、原基线 diff、可复核中间文档和阶段摘要。临时 Work/请求不泄露为已删除的执行依赖；布局原/扩大掩膜、ASS及字体和保护映射保存到操作输出，校验复制前后摘要、不覆盖已有文件、不跟随符号链接；没有自动渲染、采纳、部署或偏好保存。两个摘要不同不等于自动证明两个创意独立。报告列参考与原目标/候选的源身份匹配，只承诺没有导入外部参考来源；前置预览会重复目标源窗，目标可能本就与参考同源，实际输出存在性仍为未知。

运行时实现 SHA256：`1bd5cf5ba2ed7ec119e5841803e1b07d617f3ac1bcb0b7914af642d96ee03c7d`（`reference_transfer_ops.py`）。作者组合专测28项，含原基线scope、阶段clip冻结、选项/顺序、音频拒绝、保护保持、最终映射授权、输入变化/头竞争、第二编译器内容漂移。连同已有单参考、集成、结果预览、简报与配方回归共162项通过。较早独立复核额外7项探针通过；后续真实布局引用问题已另修并复验，不用较早71项无阻断结论替代最终版本检查。fatal Ruff 与结构检查通过。这些是技术证据，不是整卡/语义/偏好通过；最终集成精确SHA全量回归和CI另行记录。

## 最终冻结版本验收补充

最终 run4 对照在独立测试目录执行；组合输出与不读取组合产物的普通顺序编译（A准备、结果预览、字幕配方、原基线修订）候选相同。两条路径完整渲染44秒，文件摘要同为 `cc6ddd3c002cfdb45a1cea730a41a3ac2be3731bcae91c59de17747a3abb5d3f`；全程解码 RGB 摘要 `1e771d5303ee66d032662022a0fa22839f8f126a3f4045bc109fd2e95a7d28ed`、PCM 摘要 `4d3741b29a7df692fa0a2d9f0f52d5328f23aa6ab431207ea866524a3d638e8d` 也分别一致。证明显式组合等价于既有机制的顺序应用，不证明新增审美提升。

最终报告校验了46个运行时文件、14份回执和两条视频的实际摘要。补充审计递归核对全部11个持久证明文件（两份保护映射、两条字幕各原/扩大掩膜及ASS、字体），文件均存在且摘要吻合，无已删除临时目录依赖。原始参考资料路径未改写。报告 SHA256 `3a3cc9ff4e8966a507a408ad9c9ff6e78fba441ba3ac5189dbe25578beb822db`；补充审计 SHA256 `d84de73444ac42bf6d9380c593a8177dab0871dcc8143579951800ba3e84e491`。

试验夹具现分别读取历史原 Work 与测试副本：两者版本和完整文档分别保持初始状态，源媒体摘要不变。此前脚本覆写 store 变量，末尾重复检查副本而未直接检查原库；该断言不足已修正，较早独立复核也另行只读确认两库均未改变。不得将早期重复断言当原库未变的充分证据。

稀疏观察2秒、5秒、42秒：预览标签明确“非当前操作已成功”，返回原流程标签完整，后段保留原编辑器画面。观察不是连续观看或听审，不提供语义正确性、整卡效果、可读性全覆盖或真实用户认可。最终视频与该稀疏观察版本字节相同。自动报告的待视觉观察字段由此补充限定，不更写原报告。

失败试验保留：首次夹具引用错误机制卡路径而被拒；第二次运行时变动触发 `RUNTIME_MODULE_SOURCE_CHANGED` 正确失败；第三次虽声画对照一致，真实布局报告暴露临时证据路径失效，因此不能作为完整成功交付。最终修复持久化并在冻结运行时代码上重新执行 run4，通过上述检验。最终独立审查和集成全量结论由协调者另行记录，不把开发者自测冒充独立验收。
