# 调色反馈的有界调整（color-grade-adjust/1）

`color-grade-adjust` 把“暖一点”“对比强一些”这类反馈换成有上下限的参数增量。语言理解由调用方（通常是 Agent）按下面的映射表完成；本原子只把**累计步数**变成固定的参数增量，追加在基础调色层之后，并核对方向。

## 反馈映射表

说法换算成某一维的步数。“一点”“稍微”是 1 步；“很多”“明显”“再……很多”是 2 步；同一维的多次反馈累加。表外的说法不要猜，先问清楚。

| 维度 | +1 步的典型说法 | −1 步的典型说法 |
|---|---|---|
| `warmth` | 暖一点、偏黄一点、阳光一点 | 冷一点、偏蓝一点、清冷一点 |
| `tint` | 偏绿一点、去掉品红/粉 | 偏粉一点、偏品红、去掉绿 |
| `exposure` | 亮一点、提亮 | 暗一点、压暗 |
| `contrast` | 对比强一点、更有层次、更硬 | 对比弱一点、柔和一点、更平 |
| `saturation` | 鲜艳一点、颜色浓一点 | 淡一点、低饱和、颜色素一点 |

“回到原来”“不要这个调整”：把对应维度设回 0；全部为 0 时直接使用基础调色层，不调用本原子。

## 请求

| 字段 | 约束 |
|---|---|
| `grade` | 基础调色层，`color-grade/1`，与 color-grade-compile 相同（含 `interpretation`，可有 `strength`） |
| `steps` | `{维度: 整数}`，至少一维非零；每维的绝对值不超过上限 |
| `caps`（可选） | `{维度: 0–3}`，收紧上限（来自风格卡）；未列出的维度上限为 3 |
| `adjusted_id` | 新调色层的 ID |

## 步长与追加顺序

非零维度按以下顺序追加到基础调色层的 `ops` 之后（k 为步数）：

| 维度 | 追加的操作 | 每步 |
|---|---|---|
| `warmth`、`tint` | 一个 `white_balance`，`preserve_luminance: true` | R 增益 ×(1+0.025k)、B 增益 ×(1−0.025k)；G 增益 ×(1+0.02k)（正为偏绿） |
| `exposure` | `exposure` | 1/6 档 |
| `contrast` | `curves` 的 master S 曲线 | 码值 0.25 处下移、0.75 处上移 0.02k（负值即变平） |
| `saturation` | `cdl`（slope 1、offset 0、power 1） | saturation 1+0.08k |

基础调色层若带 `strength`，它同样作用于追加的调整：强度 0.5 时，调整也只体现一半。

## 方向核对与输出

在固定探针色（中灰、暗灰、亮灰、肤色样、天空样、植物样）上，把**每一维单独**叠加到基础调色层，与基础调色层的输出比较。单独核对是因为多维组合会互相掩盖，例如同时变暖、提亮会增加色度，掩盖饱和度的下降。报告中的探针变化是所有维度组合后的结果。

- `warmth`：中灰 b* 的变化方向与步数同号；
- `tint`：中灰 a* 的变化方向与步数反号（正为偏绿）；
- `exposure`：中灰 L* 同号；
- `contrast`：亮灰与暗灰的 L* 差同号；
- `saturation`：三个彩色探针的色度变化之和同号。

任何一维不符即 `COLOR_ADJUST_DIRECTION_NOT_OBSERVED`，不产出结果；例如基础调色层末端已把某个通道压到裁切，调整可能无效。输出 `color-grade-adjust.json`：新的 `grade`、生效的步数与上限、追加的操作、各探针的变化和方向核对结果，`adopted: false`。

## 不能据此声称

- 步长是固定参数增量，不是感知单位；同样一步在不同素材上的观感不同。
- 说法到步数的换算是调用方的解释；“高级一点”“有电影感”这类说法不在表内，不能硬套。
- 调整后的调色层是候选，仍需编译、预览，作品中还要经过保护项门禁。
