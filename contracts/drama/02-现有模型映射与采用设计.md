# 剧情附件与现有 Work 的映射

唯一作品权威仍是实际宿主；可选本地实现沿用 [work-version](../work-contract.md) 的 SQLite 历史、候选范围、CAS、恢复和读回。剧情内容包没有自己的采用数据库。

| 内容 | 所有者与映射 |
|---|---|
| 意图、模式、保护 | 原 TaskSpec 与真实用户请求 |
| 剧情人物/事件/Beat/shot | 内容包稳定 ID；不冒充 clip/asset ID |
| 当前作品修订 | 现有 Work store 的实际 version/document_sha256 |
| 附件身份 | `notes.drama_domain_ref`，按 `scope.note_keys` 控制 |
| 生成任务、费用、重试 | 运行 Agent 或已有可选执行能力；本包不新增 |
| 视听质量/真实素材 | 实际资产、版本与独立检查记录；本包不代签 |

引用对象 `schema=drama-domain-ref/0.1`，必须完整含有：`package_id`、`package_revision`、`manifest={path,sha256,size_bytes}`、`content_schema`、`base_work_version`。manifest 路径必须绝对。`base_work_version` 是准备候选时的来源版本，采用后也不等于当前头。

流程：读当前 Work → 检查/复制独立附件 → 基于最近完整文档形成候选 → 原 timeline-revise → 原 work-version commit → read 比对实际修订与非目标内容。仅更新领域引用时只开放 `note_keys=["drama_domain_ref"]`，其余范围按原合同冻结。无作品时保持 PLAN；不能为了存附件创建假空视频工程。

附件预写到 `store父目录/domain/drama/<清单SHA>/`，不覆盖已有包。prepare 成功只表示 PREPARED。提交仍使用当前头 CAS；旧候选会拒绝。新引用的 `base_work_version` 必须匹配提交前版本。已有引用沿后续普通修改保留时，来源版本不会被错误要求等于最新头；恢复历史附件也不改写其来源。

commit、restore、set-protection、relink-style-resources 在写入前核当前附件字节和领域结构；read 报告附件核验结果，异常时仍返回真实作品快照供修复。旧作品无该备注键时沿原逻辑。通常先创建真实作品再附加；原 work-variant-create 可通过 init 的 `drama_inheritance={store,expected_version}` 显式继承真实父作品，须核父版本、引用来源及附件。此来源检查不声称两个作品库之间的原子事务；普通 init 不得凭空伪造采用来源。

领域附件变更使 `content-review/drama-domain-review` 过期；仅变 notes 不使原媒体参数、渲染键或音轨自动改变。真正修改媒体仍须使用原范围和 coverage 规则。修改影响报告是依赖候选，不会自动写宿主或删素材。

采用前再次核对已读文件。此保证是**边界复检**，不保证文件系统和 SQLite 原子事务，也不防外部 A→B→A 改写。CAS 失败留下的预写文件是未采用附件；报告写入失败先读库确定结果，不重复提交。当前本地适配只处理带哈希的本地资产引用；原生宿主资产须由对应宿主适配补证据。

film 子包的 `09_storyboard.json` 继续是其唯一渲染权威。本包不注入未知字段、不自动转换 Storyboard、不启用 I1 缓存；旁路文件不得改变既有媒体身份。后续投影需独立验证。
